# Failure evidence without a removal waiver

The Register daily pilot now retains exact missing-issue evidence and the
validated baseline/state/implementation identities in its run report. The source
row preflight stops before linked document downloads only when the prior issue,
provenance and indexed identities agree and every docket/type association is
unique. Ambiguous source associations defer to the existing final ID gate.
Duplicate prior provenance records fail explicitly rather than being collapsed.

The final removal/reidentification gate is retained. No historical notice, ID,
status or currentness field is migrated. Successful/no-change corpus behavior
continues to pass the existing regressions.

The report includes a strict source diagnostic with old/fresh hashes, both row
counts, missing notice IDs/dockets and original source evidence. Exact source
bytes are kept as a non-rendering `.html.txt` file. A separately hashed HTML view
escapes the entire source inside a passive `pre` element; undecodable source is
shown as explicitly identified hex bytes. No source script executes in that view.
HTTP response headers are not included. Report writes check hashes, reject
symlink ancestors and traversal, snapshot previous report files and roll back
mutable outputs if a write fails. Such failures remain nonzero; no publisher
permission or gate is relaxed.

The actual workflow is `.github/workflows/register-daily.yml`. It supplies the
publisher's existing `baseline.json` through `--prepared-baseline`, so a failed
source check retains the exact validated main/pending identities inside the
always-uploaded report evidence. The publisher itself is unchanged. Unknown
prepared-baseline fields are rejected without echoing their values into errors.

## Offline example and limits

`offline-example-report/` is generated by the real 50→48 regression using only
the saved HTML/provenance fixtures and a disposable synthetic corpus. Its run
timestamp is the offline replay time, **not a new SOS retrieval**. It made two
fixture callback calls (synthetic issue listing and the saved contents body),
made zero public requests, and stopped before any linked detail/document request.
Its disposable corpus was removed after the report was copied here. This example
must not be used as a publishable source-refresh transaction.

The preflight would stop today's full-window incident at its affected contents
page; earlier issues in that window would still be checked normally. It does not
claim the entire real window needs only two requests. Transport failures before
an issue body is accepted may lack issue HTML evidence, but still retain a failed
report and any valid captured baseline. Historical/current legal status remains
unverified; preserving this evidence does not resolve why the two rows vanished.

`IMPLEMENTATION_RECEIPT.json` binds the final production files, snapshots,
coverage and offline example. `FINAL_MANIFEST.json` closes this supporting packet;
it does not replace the repository's source or control-plane manifests.
