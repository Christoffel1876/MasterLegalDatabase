A separately named, reproducible **partial research-discovery catalog is feasible**. Reconstructing the missing original catalog is not demonstrated. The existing catalog builder needs an admission/validation wrapper and a separate source-only reader; running its writer against the repository is not the proposed repair.

Read-only inspection found 57,420 rows in nine readable layer indexes. Every row passed `LayerIndexRecord`; all 1,243 distinct per-layer `path`/`meta_path` file references exist and their headers are not LFS pointers. This was index-schema and file-availability checking, not validation of every source body, original hash, legal date or coverage claim.

The original missing objects remain `_CONTROL_PLANE/RETRIEVAL_CATALOG.jsonl` (OID `e12d942b4c8098281d86a8e0db7a76b22512a8a75d050ff590a8e876c7b840b4`, expected 225,796,201 bytes), `08_County_Authorities/_index.jsonl` (OID `e896fc157617cfd9cd9839bf2bf955d893b66d7de514107e8b3c98dc4795c806`, 172,131,787 bytes), and `_CONTROL_PLANE/LOCAL_REVIEW_QUEUE.jsonl` (OID `c65a0f190fd5d5dca7810c47afc7e6843cd78520242add1fe6951545fe92ad00`, 72,395,471 bytes). The old catalog summary declares 178,625 records; it cannot describe a new partial build. No recovery was attempted.

Original-source references impose a separate limit. All 46 distinct CRS and 1,035 CCR indexed source paths are nonportable Windows paths. Indexed relative source paths are absent as files for all 12,453 bills, 535 executive orders and 437 session laws; 438 of 443 Register paths and 23 of 24 supplementary paths are absent. The one present supplementary reference is a derived federal-OSHA JSONL file, not a preserved publisher original. Four district and 85 municipal source references are not present files; some municipal references identify archive directories, not documents. These are exact-path findings, not proof that matching bytes do not exist elsewhere. No cross-archive recovery or filename-based remapping was attempted. For local authority identities, [the pilot index writer](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/local_pilot.py:180>) hashes the URL string and sets the update time when generating the row. That SHA is not an original-file digest, and that timestamp is not evidence of HTTP acquisition.

1. **Freeze an explicit input set and record omissions before building.** Use a new isolated input root and a hash-bound allowlist, never the repository's unfiltered manifest. Validate every admitted index row with [LayerIndexRecord](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/schemas/models.py:916>), then its exact referenced entity and locally present derived bytes, with unique IDs, confined paths and source-to-record bindings. [validate_record](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/schemas/validators.py:134>) covers canonical entity models; CCR acquisition data requires [CCRNormalizedOutputRecord](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/connectors/ccr_dataset.py:172>), and its optional `text_output_path` needs a separate validated adapter. A sampled CCR record has no `full_text`; do not index its acquisition description as rule text. Entries may be labeled `derived_record_only` when the exact local derived input validates but original custody is unresolved; original-source quotation requires verified original bytes and the matching review. Exclude unsupported or incomplete inputs with explicit reasons rather than silently count them as loaded. All entries remain research-only and currentness unverified.

2. **Reuse the catalog builder only inside that isolated, validated input root.** [build_retrieval_catalog(root)](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/retrieval_catalog.py:85>) can construct metadata discovery rows; the existing read-only command is `python -m geode.pipeline.retrieval_catalog --root /absolute/isolated-input-root --json`. It returns only a summary, not a separately named artifact. There is no output-path flag. A small new wrapper is required to serialize validated records to a proposed `.geode_runtime/retrieval-rebuild/<input-set-sha>/RESEARCH_CATALOG.local-subset.v1.jsonl`, with a strict schema, stable row ordering, input/code/policy hashes, admission/exclusion counts and a separate timestamped receipt. Do not call [write_retrieval_catalog](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/retrieval_catalog.py:131>) on the real repository: it overwrites the canonical name and summary. Do not copy the county semantic queue/map into the first isolated build: [conditional expansion](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/retrieval_catalog.py:215>) rereads the county index even when county is excluded from the manifest. Retain their omission explicitly. The local review queue is not a direct builder input, but remains an unrecovered readiness dependency.

3. **Keep ownership exclusions and source review scopes attached.** Load and pin the existing [ownership policy](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/local_source_ownership.py:211>) and follow explicit parent/source/review identities through [ownership_reason_with_parents](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/local_release_ownership.py:18>). Missing parents are not ownership approval; unresolved chains need a stated exclusion or metadata-only qualification. Never transfer Boulder city evidence to county authority. Separately, the newly prepared [manual-review inventory model](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/pipeline/manual_review_inventory.py:134>) is a usable source-identity/provenance join after its final check: the current inventory describes 46 originals, 18 explicit review links and 28 without an allowlisted link. This assessment did not rerun that inventory check. It does not rerun all review verifiers itself, and it does not create layer-index rows or transcript spans. Use its exact source/review hashes and appropriate package verifier before adding checked passages or tables; preserve unreviewed, source-structure and partially checked scopes distinctly. Do not force those records into `LayerIndexRecord`, which requires an official URL and update time that some custody records correctly leave unknown.

4. **Expose the new name through a dedicated research-discovery reader, not the normal answer pipeline.** The existing [local backend](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/orchestration/services/retrieval.py:116>) hardcodes the canonical catalog; no alternate catalog parameter exists. It can fall back to metadata when source text is missing and sets non-rule-unit candidates to `answer_safe=true`, `answer_mode=confirmed`, with absent update time represented as source version `current` ([lines 159–199](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/orchestration/services/retrieval.py:159>)). Its [passage selector](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/orchestration/services/retrieval.py:472>) can truncate/reorder prose and does not preserve table/footnote associations. A reader for the new artifact must return descriptive matches with `answer_safe=false`, `legal_currentness=not_verified`, separate retrieval/intake/publication claims, declared missing-source status and no inference from zero matches. Checked source detail can initially delegate only to the existing two-source [research lookup](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/scripts/research_source_lookup.py:463>); other results remain metadata discovery until their bounded adapters are reviewed. Neither [SQLite search indexing](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/search/index.py:152>) nor [web indexing](</Users/mcoors/Documents/Project Geode/MasterLegalDatabase/geode/web/index.py:180>) removes this contract gap: both scan corpus layers, and an alternate database filename alone does not fix the missing county input or source-review semantics.

5. **Require narrow admission and isolation tests before using the new artifact.** Test pointers/malformed JSON, dangling or tampered bodies, duplicate IDs, wrong source hash/authority, symlink and parent traversal, unsupported entity types, missing parent mappings, and schema drift. Verify identical input/code/policy hashes yield identical catalog bytes despite receipt-time changes; failures leave no partially published artifact. Check that tables retain associated headings, units, conditions and footnotes, and that current-law/absence/fee-calculation requests remain unsupported. Confirm both existing source lookups still work and that repository pointers, indexes, queues, raw manifests and defaults are unchanged. Start with a tiny allowlisted subset, then broaden only after recording accepted and rejected inputs; do not advertise 57,420 validated legal-source records from the schema-only count above.

A temporary two-row fixture proof used the existing builder and backend, with Pydantic-validated fixture JSON and no real corpus generation. Two builds produced identical record payloads, but the builder accepted a row whose source body did not exist. The backend returned that row's metadata fallback with `answer_safe=true`, `answer_mode=confirmed`, and unknown currency. This confirms why a separate admission gate and research response contract are necessary. Temporary files were removed on exit. The ordinary test suite was not rerun; no network, Git, source fetching, canonical writes, or LFS regeneration occurred.
